# Backend «Код судьбы» (PHP)

Без фреймворков и зависимостей — два PHP-файла, которые веб-сервер (Apache/nginx + PHP-FPM) выполняет напрямую, отдельный процесс запускать не нужно.

## Что где

- `register.php` — принимает `POST /api/register.php`, сохраняет заявку.
- `registrations.php` — отдаёт список заявок через `GET /api/registrations.php?key=...`.
- `csv-store.php` — общая логика чтения/записи CSV, подключается обоими файлами.
- `config.php` — читает секретный ключ администратора (из переменной окружения `ADMIN_KEY` или из `config.local.php`).
- `config.local.sample.php` — шаблон; скопируй в `config.local.php` и впиши свой ключ, если не хочешь задавать переменную окружения.
- `data/registrations.csv` — сами заявки (id, фамилия, имя, отчество, телефон, email, дата). Создаётся автоматически. В `.gitignore` — в git не попадает.

## Требования

Только PHP 7.4+ с включённым `mbstring`/`json` (это стандартные модули, обычно уже включены на любом хостинге). Документ-рут сайта должен указывать на папку `kod-sudby/`.

## Ключ администратора

Один из двух способов:

```bash
# на хостинге с поддержкой переменных окружения для PHP
ADMIN_KEY=мойсекретныйключ
```

или скопировать `config.local.sample.php` → `config.local.php` и вписать ключ туда.

Без ключа `registrations.php` всегда отвечает 401 — так заявки не окажутся доступны всем в интернете.

Просмотр: `https://твой-домен/api/registrations.php?key=мойсекретныйключ`

## Защита CSV с персональными данными

Файл `data/registrations.csv` не должен отдаваться напрямую по URL. Для Apache в `api/data/.htaccess` уже лежит запрет доступа — работает из коробки, если у хостинга включён `AllowOverride`. **Для nginx `.htaccess` не действует**, нужно добавить в конфиг сайта:

```nginx
location ^~ /api/data/ {
    deny all;
    return 404;
}
```

## Локальная проверка

```bash
cd kod-sudby
php -S localhost:3000
```

Открой `http://localhost:3000` — форма регистрации напрямую пишет в `api/data/registrations.csv`.
