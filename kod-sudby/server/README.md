# Backend «Код судьбы»

Маленький сервер без внешних зависимостей: раздаёт статику приложения (`kod-sudby/`) и сохраняет заявки с экрана регистрации в SQLite (встроенный модуль `node:sqlite`, доступен с Node 22.5+).

## Запуск

```bash
cd kod-sudby/server
node server.js
```

По умолчанию слушает `http://localhost:3000`. Порт можно задать переменной `PORT`.

Файл базы создаётся автоматически: `kod-sudby/server/data/registrations.db` (таблица `registrations`: фамилия, имя, отчество, телефон, email, дата). Папка `data/` в `.gitignore` — реальные заявки пользователей никогда не должны попадать в git.

## Просмотр заявок

Список заявок отдаётся через `GET /api/registrations`, но только если задан ключ администратора:

```bash
ADMIN_KEY=мойсекретныйключ PORT=3000 node server.js
```

Затем: `http://localhost:3000/api/registrations?key=мойсекретныйключ`

Без `ADMIN_KEY` этот эндпоинт отключён — так персональные данные пользователей не окажутся доступны всем в интернете.

## Важно про хостинг

GitHub Pages (куда сейчас задеплоен сайт) отдаёт только статику и **не может** запускать этот Node-сервер. Чтобы форма регистрации реально сохраняла данные в SQLite, приложение нужно открывать через этот сервер — либо локально на своём компьютере, либо на хостинге с поддержкой постоянно работающего Node-процесса и диска (например, VPS, Render, Railway и т.п.). На чистом GitHub Pages экран регистрации покажет ошибку «Не удалось сохранить данные» — это ожидаемо, а не баг.
